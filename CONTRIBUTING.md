# Contributing

## Set up

```bash
scripts/setup.sh                              # firmware submodule (--with-slam adds ORB-SLAM3)
python3 -m venv .venv && source .venv/bin/activate
pip install -e ".[test]"                      # add ,train for torch (vision / BC / VAE), ,rl for RL
```

ORB-SLAM3 is only needed for SLAM and its tests; build it with [docs/slam.md](docs/slam.md).

## Check your change

```bash
python -m pyflakes control vision workers shared_buffer synthetic rl scripts tests start.py
PILOT_SYNTHETIC=1 python -m pytest                  # the hardware-free suite, as in CI
OAKD_AVAILABLE=1 python -m pytest tests/test_workers.py tests/test_pipeline_integration.py   # with an OAK-D
python scripts/sim_bench.py                         # controllers: closed-loop numbers
```

For a change to the pipeline itself, also run it end to end in the dev simulator and
look at the result:

```bash
python start.py --config config_dev_local.yaml --enable-slam --control-mode pure_pursuit --recording
python scripts/render_recording.py /tmp/pilot_recordings/<run> --out /tmp/figs --truth config_dev_local.yaml
```

`render_recording.py --truth` prints the trajectory and boundary errors against the
simulator's ground truth. If you change mapping or SLAM, compare them with the
numbers in the README.

## Conventions

- **Units:** controllers work in signed units: steering +1 = left, throttle +1 =
  forward, 0 = neutral. `ctrl_buf` is [0, 1] with 0.5 neutral and steering 1 = full
  right; convert with `signed_to_unit` / `unit_to_signed` only.
- **Time:** buffer timestamps are `time.monotonic()`. Stamp sensor data with its
  capture time (`write(..., ts=...)`), never the wall clock.
- **Frames:** RGB channel order everywhere; depth in metres; SLAM world frame is
  camera-style (x right, y down, z forward), levelled to the floor; BEV uses axes
  `[0, 2]`.
- **Safety:** nothing may arm automatically, and every new output path must fail to
  neutral. The supervisor in `ActuatorWorker` is the last software layer; don't
  bypass it.
- **Paths:** configs refer to files relative to the repo root; open them through
  `control.types.resolve_path` so every entry point works from any directory.
- **Comments:** explain why, not what; no personal notes or dead code.

## Adding things

- **A controller:** see [docs/control.md](docs/control.md#adding-a-controller). Add a
  bench test next to the others in `tests/test_control_bench.py` and a reference in
  [docs/references.md](docs/references.md).
- **A segmentation network:** see [docs/vision.md](docs/vision.md#adding-a-candidate).
- **A worker:** subclass `workers.base_worker.BaseWorker` (`setup` / `step` /
  `teardown`, keep `step` short), wire it in `start.build_pipeline`, and make sure
  `tests/test_start_wiring.py` still builds every shipped config. If its crash should
  stop the car, add it to `CRITICAL_WORKERS` in `start.py`.
- **A buffer:** a typed wrapper in `shared_buffer/` with `write(..., ts=None)`,
  `decode(payload)` and `read_latest`; add it to the recorder candidates in
  `start.py` so it gets recorded.

## What not to commit

Recordings, datasets, trained models (`*.onnx` and their `.json` sidecars),
checkpoints and build output are git-ignored; keep it that way. Figures for the
docs go in `docs/images/`, generated by a script (`render_recording.py`,
`sim_bench.py --summary`) so they can be regenerated.

## Branches and pushes

Work on a branch and open a pull request. Firmware changes go to the firmware
repository and must be compiled and bench-tested (wheels off the ground) before the
submodule pointer is updated here.
